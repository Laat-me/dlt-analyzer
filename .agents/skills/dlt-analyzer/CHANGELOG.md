## 未来变更规则（必须遵守）

1. **先记录后实施**：改算法前先在本文档加条目（含变更前后指标对比）
2. **保留旧版**：被替换的算法/参数保留在代码（如 *_orig 变体）或 git 历史，不直接删除
3. **验证双口径**：任何算法改动必须同时报告 900/100 窗口与 1000 期段（或至少 100 期留出）两套指标
4. **诚实标注**：窗口拟合、重建（REBUILT）、疑似偏差必须如实标注，不得声称未经长窗口验证的数字
5. **同步推送**：每次变更连同本日志一起提交推送（GitHub MCP），本地 git 备份
