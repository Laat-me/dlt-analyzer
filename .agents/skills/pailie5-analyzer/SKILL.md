# 排列五持续分析与预测系统

## 重要声明

排列五每期开奖为独立随机事件，历史数据不能真正预测未来结果。
本技能仅供统计娱乐，不构成投注建议。

---

## 玩法与命中定义

- 每期开出 5 个位置，每位数字 0-9，开奖结果为 5 位数（如 `8 3 9 4 3`）
- 命中按**位置精确匹配**计：预测位 == 实际位 计 1，满分 5/5
- 与双色球/大乐透（无序选号）不同，排列五必须逐位猜中，命中率天然偏低，属正常现象

---

## 候选算法架构

系统维护一组可比较的候选算法，统一按 **Top-2 候选覆盖率** 评估：

| 算法 | 核心策略 | 作用 |
|------|---------|------|
| **A_freq30** | 每位按近30期频次排序 | 基线热号法 |
| **B_freq30+10** | `freq30×2 + freq10×0.8` | 当前最优候选，30期热度为主 |
| **C_freq30+10+all** | `freq30×2 + freq10×0.8 + freqAll×0.1` | 加入轻微全期热度 |
| **D_current_m1** | 旧公式 `gap×0.5 + freq5×1.5 + freq10×0.8 + (100-freqAll)×0.3` | 仅保留做回测对照 |
| **E_freq10** | 每位按近10期频次排序 | 短窗口热号法 |
| **F_freq5** | 每位按近5期频次排序 | 极短窗口热号法 |
| **G_freq30_only_all** | `freq30 + freqAll×0.01` | 稳定热号法 |

### 评估口径

- **主指标**：Top-2 候选覆盖率
- **计算方式**：每期开 5 个位置，每位给出 2 个候选数字；实际数字落入该位候选集合即计 1 分
- **满分**：每期 5/5；100 期留出集总分 500
- **目标值**：80% 仅作为优化目标，不保证可达成；最终必须按真实回测结果如实记录
- **比较记录**：凡历史回测覆盖率 **>50%** 的方法，必须写入 `model.json` 供后续对比

## 执行流程

### 步骤 0：Git 同步拉取（开始前）

```bash
cd <项目根目录> && git pull origin main --rebase 2>/dev/null || echo "pull skipped"
```

远端仓库的正式写操作统一走已配置好的 GitHub MCP（使用用户自己的 key），不要再默认依赖本地 `git push`。本地 `git commit` 只可作为临时备份，正式提交与推送以 MCP 结果为准。

### 步骤 1：读取本地数据

检查 `data/` 目录。`draws.json` 不存在 -> 首次初始化模式，必须至少建立最近 1000 期的本地全量历史库；初始化完成后后续只做累计追加，不删除旧记录。

### 步骤 2：数据获取

API: `https://webapi.sporttery.cn/gateway/lottery/getHistoryPageListV1.qry?gameNo=350133&provinceId=0&pageSize=100&termNum={termNum}&isSpecial=0`

- `gameNo=350133` 为排列五专属编号
- 返回 `lotteryDrawResult` 形如 `8 3 9 4 3`，解析为 5 位数字数组
- 分页：用 `pageNo` 参数翻页（每批 100 期，`pageNo=1` 为最新一期起），拉取直到满 1000 期（排列五每天开奖，1000 期约覆盖 1000 天）；每批间隔 400-500ms
- 注意：`termNum` 参数在排列五接口上不生效（始终返回最新页），必须用 `pageNo` 翻页

若 `draws.json` 已存在，后续同步一律采用累计追加模式：只补新期号，不因样本上限裁剪或删除旧期号。

若官方接口临时限流或分页被拦截，优先保留本地 `draws.json` 历史库，只追加最新开奖，避免因为全量拉取失败导致本次分析中断。

发现有新期号时自动触发步骤 4 对比。

### 步骤 3：候选算法搜索与预测

#### 共同统计
- 每位数字频次分布（全期 1000 / 近5期 / 近10期 / 近30期）
- 每位遗漏值（gap = 距上次出现在该位置的期数）
- 每位近期走势（近10期逐位变化）
- 重号/重复位分析

#### 900/100 回测框架
- 用前 **900 期**作为训练段，用后 **100 期**作为固定留出集
- 算法选择只能看前 900 期；后 100 期只做最终验证，禁止反复看留出集调参
- 训练段按 **30 期滚动窗口**评估算法表现
- 若某算法连续 **2 个 30 期窗口**都明显低于目标线（如 50% Top-2 覆盖率），则切换到下一候选算法
- 每次切换都要记录：触发窗口、旧算法、新算法、覆盖率变化

#### 当前优先算法（回测最优）
```
A_freq30:
score[pos][d] = freq30
```
- `freq30` = 数字 d 在该位置近30期出现次数
- 作为当前默认主算法，`B_freq30+10` 及其他算法仅作为对照或候选
- **同分规则**：若候选数字得分相同，取数字较小者，确保预测稳定可复现

#### 选号输出
- **主推**：当前最优算法每位得分最高的 1 个数字
- **Top-2 候选**：当前最优算法每位得分前 2 名，用于覆盖率统计
- **参考组**：可额外输出其他高排名算法的主推组，但不计入主指标

#### 输出格式
```
## 26213 期预测

| 位置 | 第1位 | 第2位 | 第3位 | 第4位 | 第5位 |
|------|------|------|------|------|------|
| 主推 | X | X | X | X | X |
| Top-2 | X/Y | X/Y | X/Y | X/Y | X/Y |

### 选号理由
[每位数字的依据]

### 算法说明
- 当前主算法: A_freq30
- 训练段表现: XX%
- 留出集表现: XX%
```

### 步骤 4：结果对比

新开奖出现时：
1. 找到预测记录中未验证的条目
2. 按位置计算 Top-2 候选覆盖数（实际数字落入候选集合计 1）
3. 更新 `model.json` 中当前主算法的 `performance` 统计
4. 输出对比表格：

```
## 上期对比

| 主推 | Top-2 候选 | 实际 | 覆盖位数 |
|------|-----------|------|---------|
| X X X X X | X/Y X/Y X/Y X/Y X/Y | X X X X X | N/5 |
```

5. 若当前算法在训练段连续 2 个 30 期窗口都低于目标线，则切换到下一候选算法，并在 `model.json` 记录切换原因

#### 复盘调整规则（核心原则：小步、慢调、可回滚）

- **最小样本门槛**：单次线上预测样本累计 ≥5 期后才允许调默认算法；900/100 离线回测不受此限制
- **调整依据**：以 Top-2 覆盖率为核心，优先看 900/100 留出集结果，再看训练段 30 期滚动窗口稳定性
- **调整方向**：优先替换算法，不优先微调权重；只有当多个候选算法都表现接近时，才在最优算法内部做 ±0.05 的小幅权重试探
- **调整幅度**：单次只切换一个默认算法，或只动一个权重 ±0.05，不允许一步到位式大改
- **验证期**：每次算法切换后，必须继续观察 ≥30 期训练窗口或 ≥3 期线上真实开奖，再决定是否继续切换
- **回滚条件**：替换后的算法在连续 2 个 30 期窗口都弱于被替代算法，或线上样本连续 3 期无改善，则回滚
- **记录要求**：每次切换/回滚都要在 `model.json` 的 `history` 或 `reviewNotes` 中写明：触发原因、旧算法、新算法、窗口覆盖率、留出集覆盖率、验证结果

### 步骤 5：保存预测记录

追加到 `predictions.json`，每条记录含 `predictedDigits` / `actualDigits` / `positionHits` / `verified`。
若 `draws.json` 已存在，则本次同步后必须更新 `updatedAt`、`latest` 和 `draws` 列表；已有 `draws` 只能追加新数据，不得滚动删除旧记录。

### 步骤 6：Git 提交并推送

默认使用已配置好的 GitHub MCP 直接提交到远端仓库，不再把本地 `git push` 作为常规路径。

推荐顺序：
1. 用本地文件操作完成 `data/` 内更新
2. 校验 `model.json`、`predictions.json`、`draws.json` 的一致性
3. 通过 GitHub MCP 将变更直接写入 `main`
4. 本地仓库如需保留同步历史，再单独做 `pull --rebase`

若必须保留本地命令示例，仅作为兜底，不作为默认流程：

```bash
cd <项目根目录>
git add .agents/skills/pailie5-analyzer/data/
git commit -m "update: $(date +%Y-%m-%d) 排列五单模型预测"
git push origin main
```

注意：`draws.json` 属于技能的持久化历史库，不是临时缓存。只要被初始化出来，就必须和 `model.json`、`predictions.json` 一起提交到仓库。
