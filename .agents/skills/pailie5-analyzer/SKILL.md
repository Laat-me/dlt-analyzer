# 排列五持续分析与预测系统

## 重要声明

排列五每期开奖为独立随机事件，历史数据不能真正预测未来结果。
本技能仅供统计娱乐，不构成投注建议。

---

## 玩法与命中定义

- 每期开出 5 个位置，每位数字 0-9，开奖结果为 5 位数（如 `8 3 9 4 3`）
- 命中按**位置精确匹配**计：预测位 == 实际位 计 1，满分 5/5
- 与双色球/大乐透（无序选号）不同，排列五必须逐位猜中，命中率天然偏低，属正常现象

---

## 单模型架构

| 模型 | 核心策略 | 适用场景 |
|------|---------|---------|
| **m1 冷热折中** | gap×0.5 + freq5×1.5 + freq10×0.8 + (20-freqAll)×0.3 | 每位独立评分，兼顾遗漏与热度 |

`freqAll` 基于 200 期样本：每位 10 个数字理论均出 20 次，故用 `(20-freqAll)` 衡量全期偏冷。

## 执行流程

### 步骤 0：Git 同步拉取（开始前）

```bash
cd <项目根目录> && git pull origin main --rebase 2>/dev/null || echo "pull skipped"
```

远端仓库的正式写操作统一走已配置好的 GitHub MCP（使用用户自己的 key），不要再默认依赖本地 `git push`。本地 `git commit` 只可作为临时备份，正式提交与推送以 MCP 结果为准。

### 步骤 1：读取本地数据

检查 `data/` 目录。`draws.json` 不存在 -> 首次初始化模式，必须至少建立最近 200 期的本地全量历史库；初始化完成后后续只做累计追加，不删除旧记录。

### 步骤 2：数据获取

API: `https://webapi.sporttery.cn/gateway/lottery/getHistoryPageListV1.qry?gameNo=350133&provinceId=0&pageSize=100&termNum={termNum}&isSpecial=0`

- `gameNo=350133` 为排列五专属编号
- 返回 `lotteryDrawResult` 形如 `8 3 9 4 3`，解析为 5 位数字数组
- 分页：以最新期号作 `termNum` 拉首批；若不足目标期数，用返回的最小期号作新 `termNum` 继续拉取，直到满 200 期（排列五每天开奖，200 期约覆盖 200 天）
- 每批间隔 400-500ms

若 `draws.json` 已存在，后续同步一律采用累计追加模式：只补新期号，不因样本上限裁剪或删除旧期号。

若官方接口临时限流或分页被拦截，优先保留本地 `draws.json` 历史库，只追加最新开奖，避免因为全量拉取失败导致本次分析中断。

发现有新期号时自动触发步骤 4 对比。

### 步骤 3：单模型预测

#### 共同统计
- 每位数字频次分布（全期 200 / 近5期 / 近10期 / 近30期）
- 每位遗漏值（gap = 距上次出现在该位置的期数）
- 每位近期走势（近10期逐位变化）
- 重号/重复位分析

#### m1 评分（冷热折中，每位独立）
```
score[pos][d] = gap×0.5 + freq5×1.5 + freq10×0.8 + (20-freqAll)×0.3
```
- `gap` = 数字 d 在该位置最近遗漏期数（必须显式判断 `=== undefined`，`0` 是合法值）
- `freq5` / `freq10` / `freqAll` = 对应窗口内该位置出现次数
- 高分 = 遗漏补偿 + 近期活跃 + 全期偏冷平衡

选号：每位取 score 最高的数字组成 5 位主推；同时输出每位 Top 2 候选供参考。

#### 输出格式
```
## 26213 期预测

| 位置 | 第1位 | 第2位 | 第3位 | 第4位 | 第5位 |
|------|------|------|------|------|------|
| 预测 | X | X | X | X | X |
| 候选 | X/Y | X/Y | X/Y | X/Y | X/Y |

### 选号理由
[每位数字的依据]
```

### 步骤 4：结果对比

新开奖出现时：
1. 找到预测记录中未验证的条目
2. 按位置计算命中数（预测位 == 实际位 计 1）
3. 更新 `model.json` 中 `performance` 统计
4. 输出对比表格：

```
## 上期对比

| 预测 | 实际 | 位置命中 |
|------|------|---------|
| X X X X X | X X X X X | N/5 |
```

5. 按学习率 0.05 调整模型权重，遵循下面的**复盘调整规则**

#### 复盘调整规则（核心原则：小步、慢调、可回滚）

- **最小样本门槛**：模型累计预测 ≥5 期后才允许调整权重；此前每期只记录观察结论，不调权重
- **调整依据**：对比"位置命中分布"与历史基准（如和值 18-28 核心区间、重号 78% 频率）。当模型选号系统性偏离已验证规律（如连续多期和值超标、遗漏回补策略连续踏空）时，才触发调整
- **调整方向**：按具体失效环节微调对应权重，例如：
  - 追冷（gap）连续踏空 → 降 gap、升 freq5/freq10
  - 和值持续偏高/偏低 → 加入和值约束权重，或在候选位降权极端数字
  - 重号预测不足 → 提高重号位权重
- **调整幅度**：单次只动一个权重 ±0.05，不允许一步到位式大改
- **验证期**：每次调整后，必须再观察 ≥3 期新开奖结果，期间不再调整
- **回滚条件**：调整生效后连续 3 期命中率继续下滑，或与调整前相比无改善，则回滚到上一组权重，并在 `model.json` 记录回滚原因
- **记录要求**：每次调整/回滚都要在 `model.json` 的 `history` 中写明：触发原因、调整的权重与幅度、生效期数、验证结果

### 步骤 5：保存预测记录

追加到 `predictions.json`，每条记录含 `predictedDigits` / `actualDigits` / `positionHits` / `verified`。
若 `draws.json` 已存在，则本次同步后必须更新 `updatedAt`、`latest` 和 `draws` 列表；已有 `draws` 只能追加新数据，不得滚动删除旧记录。

### 步骤 6：Git 提交并推送

默认使用已配置好的 GitHub MCP 直接提交到远端仓库，不再把本地 `git push` 作为常规路径。

推荐顺序：
1. 用本地文件操作完成 `data/` 内更新
2. 校验 `model.json`、`predictions.json`、`draws.json` 的一致性
3. 通过 GitHub MCP 将变更直接写入 `main`
4. 本地仓库如需保留同步历史，再单独做 `pull --rebase`

若必须保留本地命令示例，仅作为兜底，不作为默认流程：

```bash
cd <项目根目录>
git add .agents/skills/pailie5-analyzer/data/
git commit -m "update: $(date +%Y-%m-%d) 排列五单模型预测"
git push origin main
```

注意：`draws.json` 属于技能的持久化历史库，不是临时缓存。只要被初始化出来，就必须和 `model.json`、`predictions.json` 一起提交到仓库。
